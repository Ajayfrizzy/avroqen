## Evidence-aware asset checklist

- [ ] README and [canonical judge walkthrough](M9_JUDGE_DEMO.md) contain exact
  do-X-see-Y steps and distinguish SAMPLE, automated, sandbox and owner-verified
  public deployment evidence.
- [ ] Every screenshot/video frame keeps SAMPLE labels visible and is entered in
  the [M9 artifact manifest](evidence/m9/README.md) with source commit, capture
  time, route, viewport, SHA-256, privacy review and actual validation status.
- [ ] No asset labels the deployment/initialization transaction as a payment or
  claims an unrecorded funded mandate, recipient delta or settlement.
- [ ] Project description and architecture summary identify owner authority,
  restricted agent scope, independent evidence, onchain enforcement and unknown
  outcome quarantine without claiming an independent audit.
- [ ] Demonstration instructions require no wallet for SAMPLE access and identify
  M8 live acceptance as pending.
- [ ] Repository URL, hosted URL if approved, human-published X post, screenshots,
  video and any receipt links have been opened from a signed-out browser.
- [ ] Credentials, cookies, signatures, private source records, local paths and
  protected runtime evidence are absent from every public asset.
- [ ] Primary proof remains BLOCKED, Testing FullAccess key RETAINED and financial
  operations DISABLED unless a later separately authorized record changes them.

The October 29 snapshot says the repository must be public by its stated deadline,

publication, X posting, any mainnet action and the final submission.

## Pre-submit gates
- [ ] Owner confirms final brand/project name
- [ ] Public repo and green CI
- [ ] Working demo, true onchain receipts and clearly labeled simulation where used
- [ ] Document security assumptions and limitations, testnet vs production distinction
- [ ] README with reproducible judge instructions
- [ ] X post published by human with attached demo and working URL
- [ ] NEAR payout address and its required network semantics confirmed from the
  current organizer rules and by the owner
- [ ] Confirm tracks and exact field validation; no unintended data in submission
- [ ] Display final JSON, obtain explicit final approval; submit only once
- [ ] Store submission receipt/status locally outside repo; don't publish sensitive payload

## Human-only release gates

- [ ] Owner approves the exact repository commit and public visibility change
- [ ] Owner approves any hosting provider, exact zero-personal-spend cost boundary,
  domain, ingress, CSP, secrets, retention and teardown plan
- [ ] Human records/approves public screenshots and video after privacy review
- [ ] Human writes or approves and personally publishes the X post
- [ ] Human supplies and confirms identity, contact, team, track, payout account,
  consent and all other current organizer-required fields
- [ ] Full final payload and destination are shown to the human for an explicit yes
- [ ] Submission receipt is retained privately; no retry occurs unless current
  organizer rules permit it and uncertainty handling is reviewed

Documentation preparation is not permission to publish, provision, spend, post or
submit. RumptyCloud credits and capabilities remain unverified; do not require a
personal card or silently substitute a paid service.
