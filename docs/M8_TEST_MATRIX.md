## Cross-cutting M8 regressions

- `tests/e2e/settlement.spec.ts`: failed status/detail refresh hides prior balances and disables action; recovery; stale mandate response; unknown without unverified link; tampered API transaction rejected before wallet.
- `tests/e2e/journey.spec.ts`: desktop/390px role steps, policy versus funding, no offchain completion inference, unknown warning, unavailable refresh, signed-out and scope-mismatch denial.
- `tests/e2e/proposals.spec.ts`: local-byte hashing/exact one-yocto conversion on desktop/narrow view, scoped transport, idempotent retry, expired/disabled/denied UI and bounded proposal.
- `tests/unit/evidence-file.test.ts`: exact Unicode/newline bytes, empty/oversized/active file rejection. Existing evidence browser tests preserve independent-source assertions and separate owner approval.
- M1/M2 database tests retain expiry, single-use/concurrent nonce, logout/session invalidation, origin/CSRF/browser binding, FullAccess key checks, cross-tenant denial, role/agent disable and immutable policy.
- Monitoring is advisory; incident transitions cannot mutate custody. External operator liveness, device/browser trust, real source honesty, compromised RPC and retained deployment key remain separate trust limits.

All twenty scenarios have automated coverage; this is not a claim that every scenario has passed at every test level. Live/physical evidence remains pending under the runbook. Sandbox callback-removal uses a deliberately modified local test artifact to model loss; it is not the approved deployment artifact.
